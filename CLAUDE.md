# CLAUDE.md — Body of Evidence

Project memory for Claude Code sessions. Keep this current when architecture or conventions change.

## What this is

Open-source, version-controlled evidence platform for transparent, reproducible investigations built from primary sources. **Pre-alpha (schema v0.2). No investigations published yet.** Structured YAML is the canonical source of truth; markdown/pages/MCP are generated views.

## Core invariants (do not violate)

1. **Published entity version files are never modified.** Not content, not status. New version = new file, same `id`, new `version_id`.
2. **Supersession lives in `package.yaml`** (the manifest), never in the superseded file. There is no `superseded` status. Manifests are mandatory, path-contained, and list exactly one current version per id.
3. **Polarity lives on `ClaimEvidenceLink`**, never on Evidence. Evidence has no claim references.
4. **References are single-direction** (link→claim, link→evidence, assessment→claim). Backlinks are derived, never stored.
5. **Conclusion ≠ confidence ≠ dispute status.** Three separate Assessment fields. "Contested" is not a confidence level.
6. **Confidence labels:** 1=speculative, 2=weak, 3=moderate, 4=strong, 5=near_certain. Ordinal, not probabilistic.
7. **Tier A/B sources need a SHA-256 artifact digest.** URLs locate; digests identify.
8. **IDs:** `boe:<type>:<ulid>` stable across versions; `version_id` bare ULID per version. Crockford Base32 — no I, L, O, U; first char 0–7. **Repeated stable ids across files are VALID** (that is the versioning model); version_ids are globally unique. Do not "fix" duplicate ids without checking version_ids first.
9. **Every reference made BY a CURRENT entity version must resolve to the manifest's CURRENT version of the target id** — not merely to "a file with this id exists" (D-021/H-20, the highest-severity finding across the first seven rounds). The "made BY a current entity" qualifier is load-bearing (D-023/H-21): a historical/superseded referencing file is exempt from this rule — it still gets `REF_NOT_FOUND`/`REF_TYPE_MISMATCH`/`REF_WRONG_PACKAGE` checks, just not manifest-currency — because a historical record describing what it once referenced must stay valid even after that target is later retired entirely; applying H-20 unconditionally would make keeping history at all a validation failure. This is an INTERIM rule pending D-016 (Editions should resolve historical references against the Edition that was current when the referencing file was written, not a current/not-current boolean). Manifests are parsed BEFORE ordinary reference validation, specifically so `current_maps` exists when references are checked; get this pipeline ORDER wrong again and H-20 comes back. Every field in `validate_references.py`'s `REFERENCE_FIELDS`/`NESTED_REFERENCE_FIELDS` registry is checked (D-020/H-18, D-021/M-19; this IS the complete list, enforced by a schema-scanning completeness test AND a behavioural test that dangles every entry and asserts it's actually executed — do not add a registry entry that only satisfies the completeness test), not just Revision endpoints (D-018/H-02b). A stable id CAN legitimately appear in more than one file — `id_index` is a multimap; a reference prefers a same-package match and only flags `REF_WRONG_PACKAGE` when none exists (D-020/H-17; a naive single-owner index produces false positives). There is deliberately no way yet to declare "package A depends on package B". A symlink is rejected everywhere — a package ROOT, live OR DANGLING (D-019/H-15, D-023/H-22: `validate.py`'s discovery filter is `p.is_symlink() or p.is_dir()`, not `p.is_dir()` alone, since a dangling symlink fails `is_dir()` and was previously invisible), a manifest-listed entity path (D-018/M-11), an ordinary unmanifested entity file (D-020/H-19), AND any directory or non-YAML file (D-021/M-20) — before any file is ever read, and this now holds under EVERY standalone `--check`, not just `references` (D-025/M-27: `schema`/`ids`/`orphans`/`provenance` used to pass vacuously on a package containing an unmanifested internal symlink, because `find_entity_files` already silently excludes symlinks by design and nothing told the other four checks that had happened). Traversal itself is fail-closed (D-023/M-22, generalized to one shared walk per package by D-025/M-24): an unreadable subdirectory produces a `PACKAGE_SUBTREE_UNREADABLE` diagnostic instead of being silently omitted from results, since `os.walk` without `onerror` (and `pathlib.rglob`, which has the same underlying behaviour) both swallow that failure by default. Every one of these checks now runs from a single `ValidationContext` whose roots are DERIVED from its discoveries, so the supported API cannot receive contradictory roots and discovery (D-026/H-23): validators no longer take package roots and discovery as two separate arguments, and `validate.validate_paths()` — the supported API — has no parameter through which caller-supplied validation state can enter, and `ValidationContext.for_paths()` is the controlled discovery path it uses. Neither PREVENTS an in-process caller from constructing a `PackageDiscovery` directly and getting a vacuous pass; that residual is documented, tested as still-present, and out of scope by design (D-027/H-24).
10. **Validation must never be vacuous.** `validate.py` fails on empty runs; fixtures prove both directions with exact, duplicate-preserving diagnostic assertions (structured `Diagnostic(code, validator, path, message, location)`, compared as a sorted list not a set — D-019/M-07b closed the gap where a set silently dropped duplicate diagnostics).

## AI contribution limits

`AI_GUIDELINES.md` governs what Claude Code (and any AI tool) may do in this repo. Read it before touching investigation content. Summary: AI may draft structure, write tooling/schema code, and assist search/summarisation — but may **not** generate evidence claims, assign confidence levels, produce source citations, or have AI-drafted assessment text pass as human analysis without disclosure. This applies to investigation *content* work, not to schema/validator engineering.

## Commands

```bash
pip install -r scripts/requirements.txt   # pinned deps (needs jsonschema>=4.18 + referencing)
python3 scripts/validate.py --self-test   # valid fixtures must pass, invalid must fail
python3 scripts/validate.py               # validate investigations (fails if none exist; --allow-empty to override)
python3 -m pytest tests/ -q               # 124 tests: fixtures, exact diagnostic assertions, CLI-level integration, schema-completeness scan, registry-executability scan (REF_NOT_FOUND + REF_NOT_CURRENT, current-source AND historical-source), one-walk/one-read proofs, ValidationContext self-consistency and discovery-immutability proofs
COVERAGE_PROCESS_START="$PWD/.coveragerc" PYTHONPATH="$PWD/.github/coverage-subprocess" python3 -m pytest tests/ --cov=scripts --cov-report=term-missing  # same, plus local coverage % — the env vars reproduce CI's subprocess coverage for the CLI-level tests (see .coveragerc); omit them and validate.py itself reports 0% (no threshold enforced — see DECISIONS.md)
python3 scripts/validate.py --root <dir>  # validate an arbitrary package directory instead of <repo>/investigations (D-019/M-15; --root and its enumeration are error-handled — D-020/M-18, D-021/M-21)
python3 -c "from ulid import ULID; print(ULID())"  # generate a new version_id/id ULID
```

CI (`.github/workflows/validate-schema.yml`) runs pytest + self-test + investigations with `--allow-empty` (remove that flag when the first real investigation lands).

## Layout notes

- `schema/` — 16 JSON Schemas (draft 2020-12). `common.schema.json` holds shared defs. `package.schema.json` is the manifest.
- `fixtures/valid/harbour-tender-inquiry/` — complete fictional package; must pass every check. Contains a superseded claim version (same id, different version_id, absent from manifest) + connecting Revision — this PROVES the versioning workflow; do not "clean it up". `fixtures/invalid/*` — fifteen packages, one violated invariant each (incl. FIVE real tracked symlinks: manifest-symlink-escape's entity-path symlink, investigation-root-symlink's package-ROOT symlink, unmanifested-symlink's not-listed-in-package.yaml entity symlink, broken-unmanifested-symlink's DANGLING one, and symlinked-subdirectory's symlinked DIRECTORY — all five are SUPPOSED to be there; the dangling one is excluded from `.yamllint`'s scan on purpose, see that file). Fixtures derive from the invariants, never from current validator behaviour (the original duplicate-id fixture enshrined a wrong invariant; see D-015). `fixtures/cross_package/{pkg-a,pkg-b}` — two packages sharing a stable id on purpose, validated TOGETHER by dedicated tests (not the self-test loop, which only ever validates one package directory at a time) to prove package-scoped revision ownership (D-018/H-02b), package-scoped ordinary references (D-019/H-02c), AND that a same-package match is preferred over a stale cross-package one (D-020/H-17).
- `scripts/boe_files.py` — shared file discovery AND the `Diagnostic(code, validator, path, message, location)` type every validator returns (D-018/D-019). All validators use it (scans .yaml AND .yml, rejects duplicate YAML keys, refuses to descend into a symlinked package root OR read/traverse ANY individual symlink anywhere in a package — file, directory, or non-YAML — D-020/H-19, D-021/M-20). `ValidationContext` (D-026/H-23) is the SINGLE input to every `run_*_validation` function — it replaced a `investigation_paths` + optional `discoveries` pair that nothing reconciled, and which let an empty discovery paired with a known-invalid root return `passed=True, errors=[]`. Its `roots`/`real_roots` are DERIVED properties over its discoveries, so the two cannot disagree; `ValidationContext.for_paths(paths)` is the ONLY factory. `PackageDiscovery` (D-025/M-24) walks EACH package root exactly ONCE via `_walk_package` — the one function in the codebase that touches the directory tree — producing entity files, internal symlinks and traversal errors together, and then reads each document's RAW BYTES once into `DiscoveredDocument(path, raw, digest, read_error)` (D-026/M-29, corrected by D-027/H-24), including the manifest. Validators call `doc.parse()` — via `context.entities()`/`documents()`/`document_for()` — which builds a FRESH object graph per call, so one validator mutating what it got back cannot corrupt another's view (D-026 shared a single mutable dict and a reviewer flipped a failing package to passing by editing it). The precise guarantee: ONE filesystem read per document per run, every validator parsing IDENTICAL bytes (checkable via `digest`), no cross-validator interference. NOT immutability of the context, and NOT a TOCTOU guarantee against the filesystem — do not claim either; closing TOCTOU needs the digests re-verified at publication, deferred to D-016. **A `PackageDiscovery` CAN be fabricated by an in-process caller, and this is documented rather than prevented (D-027/H-24).** D-026 tried to prevent it with a module-private proof-of-walk token; a reviewer imported `boe_files._WALK_TOKEN` and got a clean pass on a known-invalid package, because a leading underscore is a naming convention, not access control. The token is gone. **`validate.validate_paths(paths, schema_dir)` is the supported programmatic entry point** — it takes paths plus ordinary configuration (`checks`, `allow_empty`), never caller-supplied validation state, and builds its own context — and `ValidationContext`/`PackageDiscovery`/`DiscoveredDocument` are INTERNAL, outside the integrity claims this project makes. Do not reintroduce a mechanism that resembles enforcement; if a property cannot be enforced, state the boundary. `test_a_fabricated_discovery_is_not_claimed_to_be_prevented` deliberately asserts the residual vacuous pass STILL happens, so the honest boundary cannot drift back into an overclaim. Discovery's remaining `__post_init__` checks (contents inside the root, symlinked-root discovery empty, collections are tuples) are self-consistency guards against a factory bug, NOT security controls. `validate.py`'s `run_all_checks` builds ONE context and passes it to all five checks; `test_run_all_checks_walks_each_package_exactly_once` proves the I/O invariant by patching `_walk_package` itself (D-026/L-12), and `test_each_document_is_read_exactly_once_per_run` does the same for reads. `preflight_diagnostics(context, validator)` is called at the top of ALL FIVE `run_*_validation` functions from that same context — so a standalone `--check` run fails closed on a symlinked root, an internal symlink, OR an unreadable subtree (D-023/M-22, D-025/M-27). The lower-level `find_entity_files`/`find_all_symlinks`/`find_traversal_errors` functions remain as directly-tested primitives but are called from no validator entry point. **Per-validator `__main__` blocks REFUSE to run** (printing the supported command, exiting non-zero) — `validate.py --check <name> [--root DIR]` is the only CLI (D-027/M-31: four of them crashed on startup for a whole commit because nothing executed them, and each duplicated discovery with a weaker `p.is_dir()` filter carrying D-023/H-22's dangling-symlink blindness; deleting them outright was tried and made those commands exit 0 in silence instead). Any new validator must take a `ValidationContext`, call `preflight_diagnostics`, never accept roots and discovery as separate parameters, and never build its own context.
- `scripts/validate_references.py`'s `REFERENCE_FIELDS`/`NESTED_REFERENCE_FIELDS` (D-020/H-18, made executable not just descriptive in D-021/M-19) — the single source of truth for which schema fields get reference-checked AND resolved against manifest currency (D-021/H-20), kept honest by `tests/test_validation.py::TestReferenceRegistryCompleteness`, which scans every schema for boe-ID-pattern fields and fails if the registry and the schemas disagree in either direction, PLUS a behavioural test that dangles every registry entry and asserts each one is actually checked. Adding a reference field to a schema without a matching registry entry WILL fail a test — that is the point.
- `investigations/_template/` — copy to start an investigation. Includes `package.yaml` and `links/`.

## Conventions

- Conventional commits (`feat:`, `fix:`, `schema:`, `docs:`; `!` for breaking).
- British/American English consistent per file (docs currently use organisation with -s).
- Fixture/example data must be fictional or safely historical; politically neutral where possible.
- When schemas change: update examples, fixtures, tests, TERMINOLOGY.md, and ARCHITECTURE.md together — the test suite catches example/schema drift.
- Remote: `origin` → `github.com/egarcia74/body-of-evidence` (public). Never push without being asked, even though the repo is already public.
